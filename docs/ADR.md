## ADR-001: Kotlin как основной язык

**Статус:** Принято  
**Дата:** Август 2025

### Контекст
Первая версия справочника была настольной программой на Java. Для мобильной версии нужно было выбрать язык.

### Решение
Использовать Kotlin для всего Android-приложения.

### Обоснование
1. **Null-safety** — предотвращает целый класс ошибок времени выполнения
2. **Корутины** — простая асинхронная работа с сетью, файлами и индексацией
3. **Совместимость с Java** — используются проверенные Java-библиотеки (Apache POI)
4. **Официальный язык Android**

### Последствия
- ✅ Меньше ошибок времени выполнения, более читаемый код
- ✅ Фоновые операции без блокировки интерфейса
- ⚠️ Часть Java-библиотек требует аккуратной настройки под Android

## ADR-002: Offline-first на файловом хранилище

**Статус:** Принято  
**Дата:** Август 2025

### Контекст
Персонал работает в помещениях без связи. Доступ к справочникам и схемам нужен в любой момент.

### Решение
Хранить все базы (Excel, PDF, JSON с координатами отметок) в файлах на устройстве. Сервер используется только для получения обновлений.

### Обоснование
1. **Доступность** — данные есть всегда, независимо от сети
2. **Простота обновления** — база заменяется целым файлом, источник истины — файлы заказчика
3. **Производительность** — чтение с диска без сетевых задержек

### Последствия
- ✅ Все рабочие функции доступны без связи
- ⚠️ Данные могут устаревать при долгом отсутствии связи

**Митигация:** фоновое обновление по расписанию, проверка версий файлов на сервере.

## ADR-003: Apache POI для работы с Excel

**Статус:** Принято  
**Дата:** Август 2025

### Контекст
Справочники и графики заказчик ведёт в Excel. Нужно читать их без ручного переноса данных, а в редакторе — записывать обратно.

### Решение
Использовать Apache POI 5.2.5 для чтения и записи .xlsx.

### Обоснование
1. Проверенная библиотека с полной поддержкой .xlsx
2. Чтение стилей и цветов ячеек (используются в справочниках)
3. Запись файлов в редакторе с сохранением структуры

### Последствия
- ✅ Заказчик продолжает работать в привычном Excel
- ⚠️ Увеличение размера APK
- ⚠️ Большие файлы требуют экономии памяти

**Митигация:** постраничный кэш распарсенных таблиц (сжатый JSON), проверка целостности кэша.

## ADR-004: Собственный поисковый индекс вместо SQLite FTS

**Статус:** Принято (заменило поиск на SQLite FTS5)  
**Дата:** 2026

### Контекст
Поиск по обозначениям оборудования имеет специфику: латинские и кириллические буквы выглядят одинаково, обозначения пишутся с разными разделителями. Стандартный полнотекстовый поиск SQLite эту специфику не учитывает и требует отдельной базы данных.

### Решение
Собственный инвертированный индекс на Kotlin, файлы индекса читаются через memory-mapped доступ. Индекс строится в два этапа: сначала по обозначениям, затем полный.

### Обоснование
1. **Нормализация под предметную область** — похожие буквы, «ё»/«е», дефисы, точки, слэши
2. **Ранжирование** — точное совпадение, затем начало строки, затем вхождение
3. **Скорость** — индекс не загружается в память целиком
4. **Без лишней зависимости** — не нужна база данных

### Последствия
- ✅ Поиск быстрый и предсказуемый на больших таблицах
- ⚠️ Свой код индекса требует собственного покрытия тестами

## ADR-005: Фоновая синхронизация через WorkManager с проверкой SHA-256

**Статус:** Принято  
**Дата:** 2026

### Контекст
Обновление баз занимает время. Пользователь не должен ждать на экране, а повреждённый файл не должен попасть в работу.

### Решение
Ручное и периодическое обновление выполняются задачами WorkManager. Каждый файл скачивается во временный файл, проверяется по SHA-256 и заменяется атомарно.

### Обоснование
1. Обновление продолжается при свёрнутом приложении
2. Система сама учитывает сеть и заряд батареи
3. Одинаковые файлы повторно не скачиваются

### Последствия
- ✅ Надёжное обновление без участия пользователя
- ⚠️ Требуется уведомление о прогрессе для фоновой работы

## ADR-006: Встроенный PdfRenderer для схем

**Статус:** Принято  
**Дата:** 2025

### Контекст
Нужен просмотр PDF-схем с отметками оборудования поверх чертежа.

### Решение
Использовать встроенный `android.graphics.pdf.PdfRenderer` и собственный слой отметок.

### Обоснование
1. Нет сторонних зависимостей и лицензионных ограничений
2. Полный контроль над слоем отметок и масштабированием
3. Перерисовка видимого участка в высоком качестве при приближении

### Последствия
- ✅ Небольшой размер приложения, предсказуемое поведение
- ⚠️ Функции просмотра (масштаб, перерисовка) реализованы самостоятельно

## ADR-007: Напоминания о сменах через AlarmManager

**Статус:** Принято  
**Дата:** Октябрь 2026

### Контекст
Напоминания о проверках должны приходить точно по времени смены, даже если приложение закрыто.

### Решение
Один точный будильник AlarmManager на ближайшее напоминание; после срабатывания планируется следующее. Будильник восстанавливается после перезагрузки, смены времени и обновления приложения. Уведомления группируются: сводка смены и отдельное уведомление по каждой проверке с кнопкой «Выполнено».

### Обоснование
1. Точное время срабатывания (WorkManager не гарантирует точность)
2. Минимальная нагрузка на батарею — всегда один будильник
3. Разрешения запрашиваются только при включении функции

### Последствия
- ✅ Напоминания приходят вовремя при закрытом приложении
- ⚠️ Без разрешения на точные будильники напоминание может немного запаздывать

## ADR-008: Слоистая архитектура и малые политики

**Статус:** Принято  
**Дата:** 2025–2026

### Контекст
Функциональность росла быстро; изменения в одном модуле не должны ломать другие.

### Решение
Интерфейс (фрагменты и активности) отделён от сервисов и репозиториев. Правила синхронизации, поиска, отображения и напоминаний вынесены в небольшие классы-политики и координаторы с чёткой ответственностью; ключевые сервисы закрыты интерфейсами.

### Обоснование
1. **SOLID** — каждый класс отвечает за одно правило
2. **Тестируемость** — политики проверяются модульными тестами без устройства
3. **Изолированность изменений** — новая функция не затрагивает существующие

### Последствия
- ✅ Более 480 автотестов, быстрые и точечные изменения
- ⚠️ Больше классов в проекте

## ADR-009: Material Components и система тем

**Статус:** Принято  
**Дата:** 2025

### Контекст
Интерфейс используется в разных условиях освещения и должен оставаться контрастным и читаемым.

### Решение
Material Components и собственная система из 6 тем оформления, светлый и тёмный режимы.

### Последствия
- ✅ Контрастный интерфейс, тема под предпочтения пользователя
- ⚠️ Каждый экран проверяется во всех темах

## Резюме

Решения приняты с учётом специфики промышленного объекта: работа без связи, большие объёмы данных, требования к целостности данных и точности напоминаний.
